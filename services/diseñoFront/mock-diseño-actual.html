Configurar un analizador HL7

Borrador Sin código personalizado
💡
El simulador se comportará como el equipo configurado. Recibirá el HL7 enviado por HIS o Mirth, extraerá los datos necesarios para crear la worklist y, cuando el proceso termine, construirá el mensaje de salida definido para ese analizador.

Flujo que estás configurando

La configuración conecta el mensaje recibido con la worklist interna y la worklist con el resultado enviado.

Propiedades del mapeo

Configura cómo se extraerá el dato seleccionado del mensaje recibido.

Campo HL7 SPM-2
Valor de ejemplo M071-01
Destino interno worklist.sample_id
Uso Barcode de carga

Forma de obtener el valor

Leer directamente un campo Extrae el contenido de una posición HL7 específica.
Leer un componente Usa una posición como OBR-4.1 u OBX-5.4.
Combinar varios campos Forma un dato interno a partir de varias posiciones.
Usar un valor predeterminado Completa el dato cuando el mensaje no lo proporciona.
✓ El ejemplo contiene SPM-2, su valor no está vacío y puede convertirse correctamente en worklist.sample_id.

Prueba de extracción

{
  "source": "SPM-2",
  "rawValue": "M071-01",
  "target": "worklist.sample_id",
  "result": "M071-01"
}

Resultado y mensajes enviados por el analizador

Después de procesar la worklist, el simulador usa estas plantillas para comportarse como el equipo y responder al sistema externo.

Eventos del analizador

Resultado completado Salida

Se ejecuta cuando la worklist termina correctamente.

Error de muestra Opcional

Envía el mensaje definido cuando la muestra falla.

Cancelación Opcional

Notifica que el procesamiento fue cancelado.

Fuentes disponibles

Datos de worklist Orden, muestra, paciente, pruebas y datos personalizados recibidos.
Datos del resultado Valor, unidad, rango, estado, observación, PDF u otro archivo.
Valores generados Fecha actual, identificador de mensaje, secuencia y contador de OBX.
Valores fijos Códigos exigidos por el proveedor que no cambian entre mensajes.
